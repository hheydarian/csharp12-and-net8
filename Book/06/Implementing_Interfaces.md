# فصل ششم: پیاده‌سازی اینترفیس‌ها و ارث‌بری کلاس‌ها

این فصل به موضوع مشتق کردن انواع داده‌ای جدید از انواع موجود با استفاده از برنامه‌نویسی شیءگرایی (OOP) اختصاص دارد. شما خواهید آموخت که چگونه از اپراتورها به عنوان یک روش جایگزین برای پیاده‌سازی قابلیت‌های ساده استفاده کنید، و یاد می‌گیرید که چگونه از جنریک‌ها (Generics) برای ایمن‌تر کردن و افزایش کارایی کدهای خود بهره ببرید. همچنین با دلیگیت‌ها (Delegates) و رویدادها (Events) برای تبادل پیام بین انواع داده‌ها آشنا خواهید شد. شما تفاوت‌های بین انواع مرجعی (Reference Types) و انواع مقداری (Value Types) را مشاهده خواهید کرد و اینترفیس‌هایی را برای قابلیت‌های رایج پیاده‌سازی می‌کنید. در ادامه، یک کلاس مشتق‌شده (Derived Class) ایجاد خواهید کرد تا با ارث‌بری از یک کلاس پایه (Base Class)، قابلیت‌ها را بازآفرینی کنید، یک عضوِ ارث‌بری‌شده را اورراید (Override) نمایید و از چندریختی (Polymorphism) استفاده کنید. در نهایت، نحوه ساخت متدهای توسعه‌یافته (Extension Methods) و تبدیل انواع (Casting) بین کلاس‌ها را در یک سلسله‌مراتب ارث‌بری خواهید آموخت.

این فصل موضوعات زیر را پوشش می‌دهد:

* راه‌اندازی یک کلاس لایبرری (Class Library) و برنامه کنسول
* متدهای استاتیک و اورلود کردن اپراتورها (Overloading Operators)
* استفاده از جنریک‌ها برای بازاستفاده ایمن از انواع داده
* صادر کردن (Raising) و مدیریت رویدادها
* پیاده‌سازی اینترفیس‌ها (Interfaces)
* مدیریت حافظه در انواع مرجعی و مقداری
* کار با مقادیر نال (Null Values)
* ارث‌بری از کلاس‌ها
* تبدیل انواع (Casting) در سلسله‌مراتب ارث‌بری
* ارث‌بری و توسعه انواع داده‌ای .NET
* خلاصه‌ای از انتخاب‌های انواع داده اختصاصی

### راه‌اندازی یک کلاس لایبرری (Class Library) و برنامه کنسول

کار خود را با تعریف یک سولوشن (Solution) شامل دو پروژه آغاز می‌کنیم؛ مشابه آنچه در فصل ۵، *«ساخت انواع داده اختصاصی با برنامه‌نویسی شیءگرایی»* ایجاد کردید. حتی اگر تمامی تمرین‌های آن فصل را به پایان رسانده‌اید، دستورالعمل‌های زیر را دنبال کنید تا این فصل را با پروژه‌های کاری جدید و تازه آغاز نمایید:

1. از ابزار کدنویسی موردعلاقه خود برای ایجاد یک پروژه جدید، مطابق با مشخصات لیست زیر استفاده کنید:

* **قالب پروژه (Project template):** کلاس لایبرری / `classlib`
* **فایل و پوشه پروژه (Project file and folder):** PacktLibrary
* **فایل و پوشه سولوشن (Solution file and folder):** Chapter06
* **فریم‌ورک (Framework):** .NET 8.0 (Long-Term Support)

1. یک پروژه جدید به سولوشن اضافه کنید، مطابق با مشخصات لیست زیر:

* **قالب پروژه (Project template):** برنامه کنسول / `console`
* **فایل و پوشه پروژه (Project file and folder):** PeopleApp
* **فایل و پوشه سولوشن (Solution file and folder):** Chapter06
* **فریم‌ورک (Framework):** .NET 8.0 (Long-Term Support)
* **گزینه Do not use top-level statements:** غیرفعال (تیک آن برداشته شود تا از ساختار سنتی استفاده کنیم)
* **گزینه Enable native AOT publish:** غیرفعال

> در این فصل، هر دو پروژه نسخه .NET 8 را هدف قرار می‌دهند و بنابراین، به صورت پیش‌فرض از کامپایلر سی‌شارپ ۱۲ استفاده می‌کنند.

1. در پروژه **PacktLibrary**، نام فایل `Class1.cs` را به `Person.cs` تغییر دهید.
2. در هر دو پروژه، کدهای زیر را به فایل پروژه (`.csproj`) اضافه کنید تا کلاس `System.Console` به صورت سراسری (Globally) و استاتیک ایمپورت شود؛ همان‌طور که در نشانه گذاری زیر نشان داده شده است:

```xml
<ItemGroup>
  <Using Include="System.Console" Static="true" />
</ItemGroup>

```

1. در فایل **Person.cs**، تمامی دستورات موجود را حذف کرده و کلاس `Person` را به صورت زیر تعریف کنید:

```csharp
namespace Packt.Shared;

public class Person
{
  #region Properties
  public string? Name { get; set; } 
  public DateTimeOffset Born { get; set; }
  public List<Person> Children = new();
  #endregion

  #region Methods
  public void WriteToConsole() 
  {
    WriteLine($"{Name} was born on a {Born:dddd}.");
  }

  public void WriteChildrenToConsole()
  {
    string term = Children.Count == 1 ? "child" : "children";
    WriteLine($"{Name} has {Children.Count} {term}.");
  }
  #endregion
}

```

1. در پروژه **PeopleApp**، یک رفرنس به پروژه **PacktLibrary** اضافه کنید؛ همان‌طور که در نشانه‌گذاری زیر (فایل `.csproj` پروژه کنسول) نشان داده شده است:

```xml
<ItemGroup>
  <ProjectReference Include="..\PacktLibrary\PacktLibrary.csproj" />
</ItemGroup>

```

1. در فایل **Program.cs**، دستورات موجود را حذف کنید، کدهایی برای نمونه‌سازی از کلاس `Person` بنویسید و سپس اطلاعات مربوط به آن را در کنسول چاپ کنید؛ همان‌طور که در کد زیر نشان داده شده است:

```csharp
using Packt.Shared;

Person harry = new()
{
  Name = "Harry",
  Born = new(year: 2001, month: 3, day: 25,
    hour: 0, minute: 0, second: 0, 
    offset: TimeSpan.Zero)
};

harry.WriteToConsole(); 

```

1. اگر از ویژوال استودیو ۲۰۲۲ استفاده می‌کنید، پروژه آغازین (Startup Project) سولوشن را روی گزینه *Current Selection* (انتخاب فعلی) تنظیم کنید.
2. پروژه **PeopleApp** را اجرا کنید و به نتیجه خروجی توجه نمایید:

```text
Harry was born on a Sunday.

```

### متدهای استاتیک و اورلود کردن اپراتورها (Static methods and overloading operators)

این بخش به طور خاص به متدهایی اختصاص دارد که روی دو نمونه (Instance) از یک نوع داده‌ی یکسان اعمال می‌شوند. این موضوع درباره حالت کلی‌ترِ متدهایی که روی صفر، یک یا بیش از دو نمونه اعمال می‌شوند، نیست.

من می‌خواستم به متدهایی فکر کنم که روی دو نمونه از کلاس `Person` اعمال می‌شوند و در عین حال می‌توانند به اپراتورهای دودویی (Binary Operators) مانند `+` و `*` تبدیل شوند. جمع کردن دو انسان با یکدیگر نشان‌دهنده چه چیزی خواهد بود؟ ضرب کردن دو انسان در یکدیگر چطور؟ پاسخ‌های بدیهی، ازدواج کردن و بچه‌دار شدن هستند.

ما متدهای خود را به‌گونه‌ای طراحی خواهیم کرد که بتوانیم داستان لامک (Lamech)، دو همسرش و فرزندانشان را مدل‌سازی کنیم؛ همان‌طور که در آدرس اینترنتی زیر توصیف شده است:
[https://www.kingjamesbibleonline.org/Genesis-4-19/](https://www.kingjamesbibleonline.org/Genesis-4-19/)

ما ممکن است بخواهیم دو نمونه از `Person` بتوانند با یکدیگر ازدواج کرده و تولیدمثل کنند. می‌توانیم این قابلیت را با نوشتن متدها و اورراید کردن اپراتورها پیاده‌سازی کنیم. متدهای نمونه (Instance Methods) اقداماتی هستند که یک شیء روی خودش انجام می‌دهد؛ در حالی که متدهای استاتیک (Static Methods) اقداماتی هستند که خودِ نوع داده (Type) آن‌ها را انجام می‌دهد.

اینکه کدام روش را انتخاب می‌کنید، بستگی به این دارد که چه چیزی برای آن اقدامِ خاص، منطقی‌تر به نظر می‌رسد.

> **توصیه اصولی (Good Practice):** داشتن هم‌زمان متدهای استاتیک و متدهای نمونه برای انجام اقدامات مشابه، اغلب منطقی است. به عنوان مثال، نوع داده‌ای `string` هم دارای متد استاتیک `Compare` و هم متد نمونه‌ی `CompareTo` است. این کار انتخاب نحوه استفاده از این قابلیت را به عهده برنامه‌نویسانی می‌گذارد که از نوع داده شما استفاده می‌کنند و به آن‌ها انعطاف‌پذیری بیشتری می‌دهد.
